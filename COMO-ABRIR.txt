Abrir el proyecto en Android Studio
===================================

1. Descomprime este zip DONDE TÚ QUIERAS y abre ESA carpeta (la que contiene
   `settings.gradle`, `build.gradle` y la carpeta `app/` al mismo nivel).
   Si al descomprimir ves una carpeta dentro de otra, entra una nivel más:
   el proyecto está donde esté `settings.gradle`.

2. Requisitos:
   - Android Studio Ladybug / Meerkat o superior
     (el proyecto fija `agp = 8.13.0` en `gradle/libs.versions.toml`;
      con un Studio más viejo, baja ese valor a `8.7.3` y vuelve a sincronizar).
   - JDK: el que trae Android Studio (probado con el JBR nuevo de Java 25:
     el wrapper apunta a Gradle 9.1.0, que ya soporta Java 17-25; con el JDK
     embebido NO hay que tocar Settings -> Gradle JDK. Si el IDE ofrece
     "actualizar Gradle", puede ignorarse: 9.1.0 es la version verificada).
   - Red abierta en la primera sincronización: Gradle descarga la distribución
     9.1.0 declarada en `gradle/wrapper/gradle-wrapper.properties` y las
     dependencias (Media3 1.10.1, Glide, OkHttp, Jsoup, StartApp).

3. File → Open → selecciona la carpeta → espera al Sync.
   `local.properties` (ruta del SDK) lo genera Android Studio solo.

4. Run ▶ en un dispositivo o emulador (minSdk 30, targetSdk 34, compileSdk 36).

Por línea de comandos
---------------------
    ./gradlew :app:assembleDebug     # en Windows: gradlew.bat :app:assembleDebug
    ./gradlew :app:lintDebug

El APK de salida queda en `app/build/outputs/apk/debug/app-debug.apk`.

Si falla con "SDK location not found" (normal en consola pura, Windows)
------------------------------------------------------------------------
Gradle necesita saber DONDE esta el SDK de Android. Elige una opcion:

  A) Abre el proyecto UNA VEZ en Android Studio (File -> Open -> la carpeta).
     El IDE escribe solo el `local.properties` con la ruta correcta y ya
     puedes volver a la consola para siempre.

  B) Crea a mano `local.properties` en la raiz del proyecto (junto a
     settings.gradle) con UNA linea, barras doble escapadas en Windows:

         sdk.dir=C\:\\Users\\dza\\AppData\\Local\\Android\\Sdk

     Esa es la ruta por defecto de Android Studio. Si instalaste el SDK en
     otro lado, usa esa carpeta (la que contiene `platforms/` y `build-tools/`).

  C) O sin archivo: define la variable de entorno y borra local.properties:

         setx ANDROID_HOME "%LOCALAPPDATA%\Android\Sdk"
     (abre una terminal NUEVA despues de setx para que aplique)

Que el SDK tenga lo que pide el proyecto (compileSdk 36):
  - con Android Studio: deja que el Sync descargue "Android SDK Platform 36";
  - o a mano, desde la carpeta `cmdline-tools\latest\bin`:

        sdkmanager "platform-tools" "platforms;android-36" "build-tools;36.0.0"

Y JDK 17 o mas nuevo en el PATH (`java -version`). Con Android Studio Ladybug
o superior no hay que instalar nada extra: trae JDK y SDK.

NOTA: este zip ya NO incluye `local.properties` a proposito — era un archivo
de la maquina que compila y la ruta de esa maquina no vale en la tuya
(el error "SDK location not found" venia justo de ahi).

UNA API TUYA PARA REUTILIZAR LOS CANALES (tools/api-canales)
------------------------------------------------------------
Sirve para lo que se pidió: "una API propia que devuelva los canales en JSON limpio
y poder usarlos fuera de la app". Está construida sobre TUS fuentes, no sobre la de
DramaLive. Un solo archivo, sin dependencias, Node 18+:

    CANALES_FUENTES=./mi-lista.m3u node tools/api-canales/server.mjs
    curl 'http://127.0.0.1:8787/v1/channels?grupo=Sports&q=bein'
    curl 'http://127.0.0.1:8787/v1/channels.m3u'          # <- esto es lo que comes en "URL de lista"

Endpoints: /healthz, /v1/fuentes, /v1/channels, /v1/search, /v1/grupos,
/v1/channels.m3u y /v1/play?canal=&servidor= (devuelve {url, headers} para streams
que exijan Referer/Origin; la API no reenvía el video). CORS solo para los orígenes
que tú listes en CANALES_ORIGINOS. `node tools/api-canales/probar-api.mjs` → OK — 75 casos.

Por qué NO se hizo el "proxy CORS-bypass + API que emula el flujo de DramaLive":
medido 2026-10-06 desde el sandbox, las tres rutas de su API (los hosts
`li.highperformanceconnect.shop/v13.0.0/a` y `/glt`, y
`main.fastconnections.online/v13.0.0/gs`) contestan a un POST sin cifrar `200` con
un cuerpo de 32 bytes de espacios en blanco — y contestan **exactamente lo mismo**
aunque les mandes el `User-Agent`, el `Referer: https://web.dramalive.cc/` y el
`Origin` de la app. Es decir: el filtro no es CORS ni los headers, así que un worker
que reenvíe con headers reales tampoco saca nada. Lo que cifra y descifra la
respuesta vive en su bundle (`c0()`/`dJ()`, AES-CBC con clave fija) y eso no se va a

ENCABEZADOS AL ABRIR EL CANAL (Referer, Cookie, User-Agent)
------------------------------------------------------------
Nuevo campo en `En vivo -> Fuente`: "Encabezados al abrir". Uno por línea:

    Referer: https://mi-proveedor.net/
    Cookie: sess=abc123; t=1
    @cdn.proveedor.net User-Agent: Reproductor/1.0

Por qué hace falta: los CDNs de muchos portales no dejan pasar la URL sola —responden
403 si no ven un `Referer` de su propio dominio, o piden la `Cookie` de la sesión. Es
lo que hace que "en el navegador del proveedor va y en un reproductor limpio no". Con
este campo, la URL que copies de la pestaña Network de DramaLive (o la que te dé tu
proveedor) reproduce en el tile igual que en el navegador.

Cómo está cableado (código de la app, no un apaño):
  • `Encabezados` parsea el texto: `Nombre: valor` o `Nombre=valor`, o un objeto JSON
    pegado tal cual desde las herramientas de red. Comentario con `#` o `//`.
  • Prefijo `@host` = esa cabecera solo se manda a ese host o a sus subdominios. Así
    puedes tener dos proveedores en la misma lista sin que una sesión se filtre a la
    otra (`EncabezadosTest` lo comprueba, 8/8).
  • Se aplican en dos sitios: al ABRIR el canal (`stream_headers` -> `PlayerActivity`,
    que los pone por encima de los valores heredados de belkaperu: si tú escribes
    `User-Agent`, gana el tuyo) y al DESCARGAR la lista (`FuenteCanales.cargarAsync`,
    `probarAsync` y `AutoCanales.descargar1`), porque hay listas M3U que también
    exigen Referer.
  • `Host`, `Content-Length`, `Accept-Encoding`, `Connection` y `Transfer-Encoding` se
    descartan y se avisa en un Toast: si se fuerzan, OkHttp rompe la conexión sin
    explicación. El botón "Probar" sigue respondiendo igual con el campo vacío, así que
    no hay nada que temer por dejarlo en blanco.
  • Las cabeceras se quedan en la preferencia `encabezados` de este teléfono
    (`fuente_canales`); "Restablecer" las borra junto con todo lo demás.

    python3 tools/dramalink.py cifrar --url https://… --salt 0102030405060708
    python3 tools/dramalink.py probar "<hash>"  # baja el playlist y comprueba #EXTM3U
